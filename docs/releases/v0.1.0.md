First tagged release of the GhostCal server. Until now, self-hosted instances ran whatever `main` was; `v0.1.0` gives a version to pin and to cite.

## For self-hosters

**Administration view.** List the administrators in `GHOSTCAL_ADMIN_EMAILS` (commas or spaces). These accounts get an *Administration* entry in the web app:

- open or close sign-up with one button. The choice is kept in the database. When sign-up is closed, the server refuses new accounts, including a first sign-in through SSO, and the web app hides the sign-up link;
- every account, with its creation date, last sign-in and second factor;
- suspend an account (its sessions end at once, every way in is refused) and reactivate it;
- delete an account and its data, after typing its address again. The audit log keeps that an account was deleted, not which one.

The view shows metadata only: like the rest of the server, it cannot read a calendar. An administrator cannot be suspended or deleted from the view; remove the address from `GHOSTCAL_ADMIN_EMAILS` instead.

**Pinning sign-up in your deployment files.** `GHOSTCAL_REGISTRATION=open` or `closed` fixes the state; the view then shows it without a button. Left empty (the default), the view decides, and sign-up stays open until someone closes it. Any other value stops the server at startup, rather than guessing a security setting.

Environment variables are read when a container is created: after changing `.env`, run `podman-compose up -d` again (a plain `restart` keeps the old values).

## Running this version

The compose file builds the images from the source tree:

```
git checkout v0.1.0
podman-compose up -d --build
```

The API image (also used by the worker and the scheduler) is published as well:

```
ghcr.io/stackopshq/ghostcal:v0.1.0
```

## Upgrading

The database gains `suspended_at` and `last_login_at` on `users`, an `instance_settings` table, and two row-level security policies on `users` for the administration view. The `migrate` service applies them before the app starts. Back up your database before upgrading, as for any update.

## Not yet

The iOS, Android and macOS apps do not yet show a specific message for a closed sign-up or a suspended account; the web app does.
